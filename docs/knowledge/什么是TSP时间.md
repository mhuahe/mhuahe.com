# 什么是TSP时间

## 一、什么是TSP

TSP（Timestamp）是指Unix时间戳，是一种时间表示方式。它定义为从格林威治时间1970年1月1日00:00:00 UTC（协调世界时）起至当前时间经过的总秒数。

TSP是一个数字值，例如：`1774460700`

## 二、核心特性

### 1. 全球统一性
TSP是绝对时间值，在全球任何地方、任何时区下，同一个时间戳代表的是同一个物理时刻。不存在时区差异问题。

### 2. 时区无关性
TSP本身不包含时区信息，它只记录从固定起点到当前时刻经过的秒数。时区转换仅在显示时间时才需要进行。

### 3. 数值类型
TSP通常以整数形式存储和传输，数据类型为Long或Int64。

## 三、工作原理

### 1. 存储层面
- 数据库中以BIGINT类型存储
- 后端以Long类型接收和传递
- 前端以Number类型接收

### 2. 转换逻辑
时间戳本身保持不变，只有在展示给用户时，才根据用户所在时区或指定时区转换为可读的时间字符串。

### 3. 时区转换规则
- 相同时间戳 + 不同时区 = 不同的本地时间显示
- 相同时间戳 + 相同时区 = 相同的本地时间显示

## 四、优势

1. **数据一致性**：避免因时区差异导致的数据混乱
2. **存储高效**：占用空间小（8字节）
3. **计算便捷**：便于时间差计算和比较
4. **传输可靠**：不受时区配置影响

## 五、使用规范

### 1. 后端处理
- 接收和存储时间戳时保持原始数值
- 返回给前端时保持秒级时间戳格式
- 不在后端进行时区转换

### 2. 前端处理
- 接收时间戳后根据业务需求进行时区转换
- 显示时根据用户所在时区展示本地时间
- 支持根据用户选择切换不同时区显示

### 3. 时区转换时机
仅在以下场景需要进行时区转换：
- 页面展示时
- 导出报表时
- 用户主动切换时区时

## 六、注意事项

1. **单位统一**：确保前后端使用相同的时间单位（秒或毫秒），避免单位混淆导致时间错误

2. **精度问题**：秒级时间戳适用于大部分业务场景，如需更高精度可使用毫秒级

3. **时区标识**：虽然时间戳本身无时区，但在国际化应用中需记录用户的时区偏好，以便正确显示

4. **存储规范**：统一使用BIGINT类型存储时间戳，避免使用字符串类型

## 七、常见应用场景

- 赛事时间记录
- 订单创建时间
- 用户操作日志
- 消息发送时间
- 数据同步时间戳

## 八、总结

TSP时间戳是一种标准化的时间表示方法，通过统一使用绝对时间值，从根本上解决了分布式系统和跨时区应用中的时间一致性问题。开发过程中只需遵循"存储用时间戳，展示做转换"的原则，即可确保时间数据的准确性和一致性。
